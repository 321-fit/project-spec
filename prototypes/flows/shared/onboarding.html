Step 1 — Personal data

First fullscreen step. Avatar + first name + last name + short bio. Matches live iOS — gender / DOB / weight / height are intentionally NOT collected here. They are deferred to post-onboarding settings to keep the funnel lean.

  • Avatar: 110px circular dropzone (teal-blue fallback + white user icon). Tap → native PHPickerViewController.
  • Name fields use placeholder pattern (no separate label) — matches live iOS form chrome.
  • Bio: 500-char textarea, label "About Me" above. Counter hidden until typing starts.
  • Back disabled on step 1 — account already exists, can't unwind here.

Gender + DOB historically appeared in this step per project_personal_data_selectors. Dropped 2026-05-20 because iOS already shipped without them and they aren't needed for marketplace function. Can be added to Settings later if/when search needs them.

Shared

Step 2 — Sports

Multi-select sport tile grid. Sectioned by category (Fitness/Racket/Endurance/Mind&Body/Combat) per project_sport_taxonomy — live iOS shows a flat grid, this is an explicit ask to bring section headers across when iOS catches up.

  • Title centered in header: "What sports do you coach?" (coach) / "What sports do you train?" (athlete).
  • Tiles: fit-selection-gradient + teal-600 border on .selected per feedback_selection_chips.
  • Continue stays disabled until ≥1 sport selected (visualized via .is-disabled in production; prototype pre-selects Tennis + Fitness for demo).

Section taxonomy isn't shipped on iOS yet — flag for sport-types module follow-up.

Shared

Step 3 — Location

Four push-rows: time zone, home country, home city, languages. City retained against live iOS (still being added on the native side) — useful default for search radius.

  • TZ + Country — device-detected at account creation, shown pre-filled per project_personal_data_selectors.
  • City — reverse-geocoded via GET /geo/reverse-city. If geocode unavailable, field is empty and user picks manually.
  • Languages — device locale pre-fill, multi-select. Default search filter per project_search_default_filters.
  • Changing country resets city.

Step 4 — Gym Location (coach only)

Subtitle + outlined "Add Gym Location" CTA → hands off to canonical coach/locations.html. On return, the wizard would render a card list above the Add CTA (same pattern as Training Session step) + Confirm enabled.

  • Athletes don't see this step — onboarding branches: athlete jumps from Location → Calendar (step 4 of 4).
  • ≥1 location required to Confirm.
  • Location type (in-person / online / home) is set inside the canonical flow — defaults to in-person per project_locations_decisions.
Coach

Step 5 — Training Session (coach only)

Coach creates ≥1 bookable session here. Two states — empty (Add only) and filled (list of session cards above the Add CTA).

  • Tap Add Training Session → opens the inline Training Session Setup sub-screen (Name / Sport / Location / Duration wheel / Price / Cash-Card toggle).
  • Tap pencil on card → opens the same sub-screen in edit mode.
  • Inline form vs handoff: live iOS uses an inline sub-screen (NOT a hand-off to the full coach/sessions.html) — we follow that. Differs from feedback_wizard_handoff which prefers canonical create-flow handoff; the inline session form is intentional to keep new-coach friction low.
Coach

Sub-screen — Training Session Setup

Inline create / edit form pushed from step 5. Not numbered in the step counter (no pill — title is left-aligned to signal sub-screen vs main wizard step).

  • Training Name — free text, placeholder "Basketball training".
  • Sport Type — push picker, pre-filled from step 2 selection if only one sport chosen.
  • Location — push picker, sourced from step 4 gym locations.
  • Duration — UIDatePicker wheel (Hour 0–12, Minutes 0/15/30/45). iOS-native pattern per feedback_native_pickers.
  • Price — numeric input with € prefix. Currency from user's country.
  • Cash / Card — payment acceptance toggle. Cash default. Coach can accept one or both (in production both buttons can be selected simultaneously — prototype shows mutually-exclusive for clarity).
  • Save → returns to step 5 with the new session in the list.

Note: coach/sessions.html (canonical sessions screen used outside onboarding) has more fields — recurring schedule, training type, max participants. Onboarding sub-screen is a deliberate subset.

Step 6 (coach) / Step 4 (athlete) — Calendar sync

Last step. No explicit Skip link — user can simply tap Finish without connecting (live iOS pattern). Two visual states:

  • Initial: Google + Apple rows, each with a Connect pill.
  • After Google connects: Google row shows the connected email + "Fetching calendars…" spinner. A dashed "Add Google Account" appears below — multi-account is supported. Apple still listed beneath.
  • Google → OAuth (system sheet). Apple → CalDAV push (Apple ID + app-specific password), full flow lives in coach/calendar-sync.html.
  • Header title in live iOS reads literally "Google Calendar Sync" even though Apple is also offered. Flagged — should rename to "Calendar Sync" when iOS catches up.
