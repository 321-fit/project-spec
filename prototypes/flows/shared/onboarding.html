Step 1 — Personal info

First fullscreen step of post-signup onboarding. Collects gender + DOB for both roles. Athlete additionally collects weight + height (used for personalization + future training-load features). Coach hides weight/height entirely — those fields aren't needed for marketplace function (per specs/personal-data.md § coach vs athlete fields).

iOS ref: Onboarding/OnboardingFlow.swift case .personalInfo.

  • Gender: 2-option chip group (Woman / Man) per project_personal_data_selectors.
  • DOB: tappable input → opens wheel picker sheet (same pattern as coach/personal-data.html; not rendered inline in this prototype).
  • Weight / Height: metric only (kg / cm) per project_personal_data_selectors. Suffix inline in the input field.
  • Back disabled on step 1 (account already created — can't unwind here).

Switch role in the left sidebar (Athlete vs Coach) — the weight/height block hides for coach via data-role-only="athlete".

Shared

Step 2 — Sports

Multi-select sport tile grid. 33 sports total in the canonical taxonomy (per project_sport_taxonomy), prototype shows 6 representative ones.

  • Athlete title: "Pick your sports" — what you want to train.
  • Coach title: "What do you teach?" — what you'll offer to athletes (overlay via data-role-copy).
  • Tiles use canonical fit-selection-gradient + teal-600 border on .selected per feedback_selection_chips.
  • Continue button stays disabled until at least 1 sport is selected (visualized via .is-disabled in production; prototype shows pre-selected Tennis for demo).
Shared

Step 3 — Avatar & bio

Profile photo + short bio. Avatar is optional at this step but strongly nudged with the dashed dropzone visual; bio is encouraged but not required to continue.

  • Avatar zone: 120px circular dashed dropzone → tap opens native picker (same pattern as coach/personal-data.html avatar pencil; in production fires PHPickerViewController / Android equivalent).
  • Bio: 500-char textarea with live counter. Coach copy nudges toward credentials ("years coaching, certifications, what makes your sessions different"); athlete copy nudges toward goals ("what you train for, what motivates you").
Shared

Step 4 — Location

Four push-rows: time zone, country, city, languages. Each opens a dedicated picker (sticky search + scrollable list; not rendered inline in this prototype).

  • Time zone, country — device-detected at account creation, shown pre-filled per project_personal_data_selectors.
  • City — reverse-geocoded from device GPS at onboarding (GET /geo/reverse-city). If geocode unavailable, field is empty and user picks manually per project_personal_data_selectors 2026-05-19 update.
  • Languages — device locale pre-fill, multi-select, used downstream as search filter default per project_search_default_filters.
  • Changing country resets city (no cross-country city values).

In production these pickers are full-screen pushes (same components as coach/personal-data.html s-country-select / s-city-select). For Continue to enable, all 4 rows must have a value.

Step 5 — Gym locations (coach only)

Coach picks at least one training location. Map placeholder shows where the location is + form fields for name and address. Address autocompletes via native maps service (MapKit / Google Places).

  • Athletes don't see this step — onboarding flow branches at step 5: athlete jumps from Location directly to Calendar sync (step 5 of 5).
  • Coaches add ≥1 location to continue. More locations can be added later in coach/locations.html.
  • Location type (in-person gym / online / home visit) is set per location — defaults to in-person for the first one (per project_locations_decisions).
Coach

Step 6 — First training session (coach only)

Coach creates one template session. Three fields: name, duration, price. Duration is a select with common presets (30 / 60 / 90 / 120 min).

  • One session minimum to continue — coaches need at least one bookable thing for the marketplace to surface them.
  • Sport is implicit (defaults to the first sport selected in step 2). Coach can edit + add more sessions later in coach/sessions.html.
  • Currency is the user's country's default (€ for Georgia / EU; production reads from country lookup table).
Shared

Step 5/7 — Calendar sync (optional)

Last step before complete. Only step in the onboarding flow that has a Skip for now link — everything else is mandatory.

  • Google Calendar tap → native OAuth bottom sheet. On success, return here with Continue auto-fire.
  • Apple Calendar tap → push to CalDAV connect form (Apple ID + app-specific password) — full flow lives in coach/calendar-sync.html.
  • Skip → goes straight to Complete; coach/athlete lands on dashboard with no calendar connected. User can connect later in Settings → Calendar Sync.
Shared

Complete — done

Celebration screen. Single Continue / Get started CTA → lands on the appropriate dashboard.

  • Athlete → "Let's find you the first coach" → athlete dashboard (with welcome wizard for follow-up tasks like first top-up).
  • Coach → "Your profile is now under review" → coach dashboard dst-under-review state (banner + optional boosts like Stripe / Available hours / Intro video).
  • Backend on Continue: setOnboardingCompleted() + transition account state. Server emits user.onboarded event (athlete's inviter coach gets push notification per specs/onboarding.md).

Onboarding flow ≠ dashboard wizard widget. After complete, dashboard widget is a separate checklist for remaining setup tasks (per project_onboarding_wizard).
