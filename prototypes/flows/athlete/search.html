Search · Landing

Default tab opening. Header is the anchor: left = current Sport filter chip, right = search 🔍 + map 🗺 icons. No always-on search bar — saves vertical space.

Sport anchor chip — preselected from athlete’s Sport Types in Settings. Default if empty = “All sports”. Tap → opens existing flows/coach/sport-types.html (same picker reused, not a separate component).

Multi-sport display rule:

  • 1 sport → “Tennis”
  • 2 sports → “Tennis, Padel” (this is what’s shown here)
  • 3+ sports → “Tennis, Padel +1” (max 2 names then count)

Compact filter chips row — Filters button + 4 quick toggles (Near me / Price / Today / Online). Tap chip = open relevant section in Filters.

Count + Sort link — “52 Tennis coaches near you · Recommended”. Tap sort → bottom sheet for quick switching.

One continuous coach list — no section labels. Backend ranks results by the recommendation algorithm (sport + location + activity hybrid). As athlete scrolls, ranking gracefully degrades from perfect-match to broader matches — but the UI does not label or divide them. The whole feed reads as “coaches for you”, ordered.

Decision: explicit “Recommended” / “Top rated” section labels removed — they implied the user makes a choice between sections, when really it’s one ranked stream. Cleaner, less cognitive load.

Bottom: loading spinner appears as next page fetches. Recently viewed lives in Search-text push screen, not here.

Search · Text overlay

Push screen from header 🔍. Single purpose: find coaches by name or sport keyword. Sport is also handled by the header anchor for browse, but text search lets you jump straight to results without going through the sport picker.

3 states:

  • Initial — empty input. Recent text searches only (with × to remove individual, Clear-all link). Recently-viewed coaches removed from here — they live on Dashboard as the canonical home, and search overlays in Spotify/Booking/Airbnb show queries only, not viewed items.
  • Results — list of matching coaches using the SAME card pattern as Landing/Results. Whether the query matched coach names or a sport keyword, the output looks identical: full coach cards with photo, rating, sport, city, bio, fav heart. Count shown at top (“4 coaches match ‘box’”).
  • No match — empty illustration + “Browse all coaches” CTA.

Match logic:

  • Sport keyword (e.g. “box”) — matched against 33-item sport list → filters by that Sport. No intermediate “sport-shortcut” row, just shows the coaches directly.
  • Coach name (e.g. “pav”) — substring against coach name index → shows matching coaches.
  • No locations, NLP, did-you-mean — overkill for the marketplace pattern.

Tap a card → coach profile. Single unified card system everywhere.

Filters · Full push screen

Full-height push (not bottom sheet — more room, can be scrolled comfortably, no accidental swipe-close on long sections). Show N coaches CTA pinned via flex column layout.

Sections:

  • Location — two push rows (filter-expand-row pattern, same as Languages / Coach gender below). Country → s-search-country, City → s-search-city (list scoped to selected country). Both auto-applied from Personal Data (Home country / Home city). Changing country resets city. Picking values here does NOT write back to Personal Data — Search filter is session-local.
  • Price — dual-thumb slider
  • Time of day — symmetric 3×2 tile grid with hour ranges. Each tile has a daypart icon. Multi-select. Empty = no constraint.
  • Format — multi-select chips (In-person / Online / Home visit)
  • Languages — push to multi-select screen (search + list + sticky Save). Same component as coach/personal-data.html#s-lang-select — replicated inline here for prototype clarity. Selected shows “English, Spanish” in teal.
  • Coach gender — bottom sheet (only 3 options, doesn’t warrant a full push). Single-select: Any / Female / Male.
  • Group lessons only — toggle row, inline switch (no chevron, no push).

Sport is NOT in Filters — it’s the anchor chip in the header. “More options” sub-label removed — all rows flat in one section. Experience-level filter dropped (we have coach maturity model, not user-facing experience tiers).

Selected-state pattern on push rows: when value differs from default, right-side text turns teal + medium weight. Quick visual scan of what’s active.

Sticky bottom: single full-width Show N coaches CTA. Reset lives in header (top right) — no duplication.

Default state after onboarding (memory: project_search_default_filters, updated 2026-05-19):

  • Auto-apply: Sport (header anchor) + Country + City + Languages from Personal Data
  • Default: Price=none, Time=none, Format=all 3, Gender=Any, Group=OFF
  • Reset = back to this state, not "everything cleared"

Filters · Country

Push from Filters → Location → Country row. Single-select with search; auto-dismiss back to Filters on tap. Same UX as coach/personal-data.html#s-country-select — replicated inline so back navigation returns to Search Filters, not Personal Data.

  • Pre-selected: from Personal Data → Home country (athlete's stored country)

Filters · City

Push from Filters → Location → City row. Single-select with search; auto-dismiss back to Filters on tap. Same UX as coach/personal-data.html#s-city-select — replicated inline.

  • List scoped to the currently-selected country in Search filter (NOT Personal Data country, since user may have switched). Header subtitle "Cities in <Country>" makes scope explicit.
  • Pre-selected: from Personal Data → Home city (if it belongs to current filter country); empty otherwise
  • No flag on row — city names are unambiguous within country scope
  • Picking a new city here does NOT write back to Personal Data — session-local

Prototype shows 7 Lithuanian cities. Production = paginated list via GET /api/v1.0.0/geo/cities?country=<code>&q=<search>.

Filters · Coach gender (bottom sheet)

Bottom sheet (not push) — only 3 options, doesn’t warrant a full screen. Single-select with checkmark on active row: Any / Female / Male.

Sensitive area — we expose this because some athletes have strong preference (e.g. female athletes preferring female coaches for certain sports/contexts). Defaults to “Any”.

Rule of thumb: ≤ 4 options + no sub-descriptions → bottom sheet. More options or richer rows → push screen.
