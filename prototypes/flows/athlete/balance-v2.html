Balance

Auto top-up status (hero note)

v2 — Revolut-style dashboard. Variant of balance.html (kept intact for rollback). The list-first layout is replaced by: one Balance card → analytics widgets → Recent preview → full history on its own screen.

  • Balance card (teal, single — no swiper): prepaid wallet — Available + auto-top-up note + Top up pill. The "money I have."
  • Analytics widgets (2×2 .bal-widget tiles, page-local — genuinely novel visual): This month (€245 · €175 card · €70 cash), Total spent (lifetime), Booked (planned spend = upcoming sessions → calendar), Owed (red, cash debt → my-coaches.html). These answer the same questions the old swipe "Spending" card did, so that card is dropped (decision: fork B).
  • Recent — 3 latest rows + See all ›. Plus an All transactions button. Both → History screen.
  • Why widgets, not a list — finance dashboards (Revolut/Monzo) lead with glanceable metrics; the raw ledger is one tap away, not the first thing you scroll.
  • No "Payment methods" entry — cards saved during Stripe checkout, managed inside Stripe's PaymentSheet.

Reached from Settings → Payments → Balance + Dashboard balance card. Backed by shipped endpoints (PR #541–#543). Money wire = minor units. This is a parallel module — original balance.html untouched.

Transactions (History)

Full ledger, pushed from Balance (See all / any widget). Canonical .fit-txn* rows, date-grouped.

  • Sticky header (.hist-sticky) — the search field + filter chips are pinned (CSS position: sticky; top: 0); the transaction list scrolls underneath them. Native: pin search + chips to the top of the scroll view (iOS UICollectionView pinned supplementary / Android sticky header) so filters stay reachable while scrolling.
  • Search — narrows the current chip filter by free text (coach, session, amount).
  • Filter chips — two dimensions in one row: by type (All / Spent / Top-ups / Refunds) and by payment method (Card / Cash). Single-select; method chips read data-method, type chips read data-txn.
  • Widgets deep-link with a pre-applied filter (e.g. This month → Spent).
  • Empty result → "Nothing here" no-match state.

Top up

Mode / state
Saved card (first-time)

One screen, two modes via a .fit-segmented switch at top — One-time and Automatic are mutually exclusive. No sheet-on-sheet, no inline toggle mess; a single footer CTA drives the action.

  • One-time — amount chips €50 / €100 / Custom. Footer Top up €X → native Stripe PaymentSheet (checkout: saved cards + Apple Pay + add + save). We don't build a card selector for manual — Stripe owns it.
  • Automatic — threshold (€25/€50/Custom) + amount (€50/€100/Custom) + Charge card (saved cards only, wallets excluded — off-session) + live preview. Footer = Turn on auto top-up → once on, becomes Save changes + a Turn off link. Explicit commit, no silent auto-save.
  • Off-session charge fails — two cases (Stripe MIT): declined / expired → red .fit-inline-error + Update (→ change card); authentication_required (3-D Secure) → blue info banner + Confirm (→ 3DS sheet) — NOT a dead card, one-tap re-auth. Both need a new push category.
  • Card unification — the auto-topup paymentMethodId comes from /athlete/payment-methods (one source of truth).

Stripe sheets are native (PaymentSheet for checkout) — represented here as mocks (checkout-sheet / addcard). Auto card picker = cardpick-at. Footer CTA label/action follow mode + state. Backend PR #541–#543.

Session payment — cash (detail)

Tap a cash spend row → this detail (separate screen, not the card one). Cash pill; the money is not taken from balance (paid in person), so there's no "Paid from / Balance after". Status = Paid (teal) — a cash session lands in Balance only once the coach confirms receipt; Payment shows Method: Cash · in person. Owed (not-yet-paid) cash sessions never appear in Balance — they live on the Dashboard, coach detail, and the red Owed summary widget.

Refund reason
