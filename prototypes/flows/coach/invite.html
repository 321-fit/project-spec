Select Training

Step 1 of both Invite and Schedule flows. Choose training template.

  • v6d cards in select mode (tap = select + push to next step)
  • Shows all coach's templates (personal + group)
  • Empty: coach has no templates yet → CTA jumps to settings.html#s-create
  • Loading: 2 skeleton cards
Coach

Date & Time (Personal)

Step 2 for personal training. Choose when.

  • Day strip for date selection
  • Time slots based on coach availability
  • Busy slots dimmed with event name
  • Selected slot: gradient + checkmark
  • Confirm button routes to review based on flow mode

No availability: all slots busy on this day — user picks another date. Error: inline banner with Retry (no outer banner — positioned after content, CTA remains in footer).

Coach

Date (Group)

Step 2 for group training. Day strip + event cards.

  • Day strip with dots on days that have group sessions
  • v6d event card with spots count — tap = select + push to review
  • Teal border on selected card

Empty: template has no scheduled sessions — CTA to go back and pick another template.

Coach

Invite Review

Step 3 of Invite flow — coach shares deep link with someone not yet in the app.

  • Summary card: training, date, time, location, price, "Invitation" badge
  • Optional comment field for athlete (max 300 chars with live counter — gray default, red at limit)
  • Info text: "Share the invite link..."
  • "Send Invite" → opens native iOS share sheet with deep link
  • Deep link: athlete opens → onboarding → sees invitation → Accept/Decline
  • Sending: CTA shows spinner + disabled — prevents double-tap
  • Error: inline banner above CTA with Retry. Main CTA stays active (can also retry from button).

Entry: Clients tab "+" sheet → Invite to training. URL param mode=invite (default).

Coach

Schedule: Review Request

Step 3 of Schedule training flow — coach proposes a session to an existing in-app client. Reuses 3 of 4 invite screens; differs only here.

  • Summary card: same layout but Request pill (yellow) matches 6-state calendar system
  • Recipient row: avatar + name + "Will be sent as a training request" — makes destination explicit (invite doesn't have this — athlete is anonymous until link opens)
  • Optional comment field — coach's message to athlete, shown in their Request drawer (max 300 chars with live counter — gray default, red at limit)
  • Info text: "Anna will receive this as a training request..."
  • "Send Request" → backend call → event lands in Awaiting for coach + Request for athlete inbox → snackbar confirmation → navigates back to origin

Entry points (URL param mode=schedule&origin=X):
• Client Detail ⋯ → Schedule training (origin=s-client-detail)
• Client Detail empty Upcoming → Schedule training CTA
• Calendar FAB → Schedule training (future, not yet wired)
