Coach

Select Training

Step 1 of both Invite and Schedule flows. One list of all templates — the flow branches by template type on tap.

  • v6d cards in select mode (tap = select + push to time-grid)
  • Personal template → grid → invite/schedule an athlete.
  • Group template → same grid → publish an open session (recurrence drawer, no athlete). pickTemplate('group', …) sets the branch.
  • Empty: coach has no templates yet → CTA jumps to sessions.html#s-create
  • Loading: 2 skeleton cards
Coach

Date & Time (Personal + Group)

Step 2 for personal training. Choose when.

  • Day strip for date selection
  • Time-grid (reuses .fit-timeline/.fit-hour, 96px = 1h). Tap a free band to place the block or drag it (snaps 15 min). Block snaps off any busy range to the nearest free slot.
  • Dual availability: solid gray = your own events ("You · …"); hatched = blocked (after-hours, and in schedule mode the in-app athlete's conflicts, e.g. "Anna busy"). In invite mode (external athlete) the athlete row is hidden — calendar unknown.
  • Group templates reuse this exact grid — coach drops the block where the session goes; the target-athlete row is hidden (open event, no invitee).
  • Confirm → bottom sheet: personal = link-invite / in-app schedule (by mode); group = recurrence + Publish drawer (Just this date / Weekly + days + Ends: Ongoing / On date). Picking On date expands the sheet to the large detent (.presentationDetents([.medium,.large])) and scrolls to an inline month calendar (native graphical DatePicker on device — no stacked picker sheet); swipe the sheet back down to collapse.
  • Weekly conflict review: on Publish, recurring occurrences are checked for overlaps in the 60-day generation window. If any collide → a review page (page 2 of the same sheet, no stack): own 321Fit events are hard-skipped (can't double-book yourself), external Google/Apple conflicts get a per-date Keep anyway toggle. CTA "Publish N sessions" excludes skipped dates. Same weekly time kept for athletes; rolling generation re-checks later occurrences + pushes the coach. → Publish open event, land on Calendar.

Same grid component as athlete s-booking (.fit-bk-* in fit-ui.css), mirrored. Different times per weekday (Tue 12:00 + Fri 17:00) = two separate placements from the same template — matches Google/Apple recurrence (multi-day, single time). No availability: user picks another date. Error: inline banner with Retry.

Coach

Invite Review

Step 3 of Invite flow — coach shares deep link with someone not yet in the app.

  • Summary card: training, date, time, location, price, "Invitation" badge
  • Optional comment field for athlete (max 300 chars with live counter — gray default, red at limit)
  • Info text: "Share the invite link..."
  • "Send Invite" → opens native iOS share sheet with deep link
  • Deep link: athlete opens → onboarding → sees invitation → Accept/Decline
  • Sending: CTA shows spinner + disabled — prevents double-tap
  • Error: inline banner above CTA with Retry. Main CTA stays active (can also retry from button).

Entry: Clients tab "+" sheet → Invite to training. URL param mode=invite (default).

Coach

Schedule: Review Request

Step 3 of Schedule training flow — coach proposes a session to an existing in-app client. Reuses the invite screens; differs only here.

  • Recipient source: from Client Detail the athlete is known → this flow starts at template select. From the Calendar FAB the athlete is unknown → an extra first step s-schedule-pick-athlete (pick client / invite by phone) sets the recipient, then template → time → here.
  • Summary card: same layout but Request pill (yellow) matches 6-state calendar system
  • Recipient row: avatar + name + "Will be sent as a training request" — makes destination explicit (invite doesn't have this — athlete is anonymous until link opens)
  • Optional comment field — coach's message to athlete, shown in their Request drawer (max 300 chars with live counter — gray default, red at limit)
  • Info text: "Anna will receive this as a training request..."
  • "Send Request" → backend call → event lands in Awaiting for coach + Request for athlete inbox → snackbar confirmation → navigates back to origin

Entry points (URL param mode=schedule&origin=X):
• Client Detail ⋯ → Schedule training (origin=s-client-detail)
• Client Detail empty Upcoming → Schedule training CTA
• Calendar FAB → Schedule training (origin=s-calendar → starts at s-schedule-pick-athlete)
