Stripe Connect

Lifecycle
Connected sub-mode

2 lifecycle states only: Not set up vs Connected. "Verifying" and "Action needed" are sub-modes inside Connected, not separate lifecycle states — Stripe lets the account exist (and accept card payments) even while payouts are paused, so it's misleading to model them as a different lifecycle.

  • Not set up — intro + what-you'll-set-up list + consent → Start setup pushes to onb-confirm (step 1 of 3).
  • Connected · clean — green pill "Payouts active". Full control center: Payout methods list (bank + card, mixed) → payout block (Available + Next payout always visible) → manual mode toggle → activity preview (incl. in-transit) → Disconnect. Account ID + Country meta removed (low-value).
  • Connected · verifying — blue info banner up top ("Verifying your details — usually within a few hours"). Hero pill turns blue "Payouts pending verification". Bank list + payout block stay visible (informational).
  • Connected · action — yellow warn banner up top ("Identity document needed — card payments work, payouts are paused"). Upload ID now CTA inside banner deep-links to s-stripe-onb-id. Hero pill yellow "Payouts paused".

Manual mode

Toggle switches Stripe payouts.schedule between automatic (weekly Monday) and manual. Manual hides Schedule row, shows yellow warning ("Money stays in Stripe until you tap Withdraw"), reveals Withdraw button.

Disconnect

3 sheet variants — clean (default), pending-balance (positive balance → suggest Withdraw first), active-events (future card-paid sessions → refund warn). Use JS console to preview: setStripeDisconnectVariant('pending-balance') / setStripeDisconnectVariant('active-events').

Deep-links from balance.html

stripe.html#none / #done / #verifying / #action — last two land on Connected with the matching banner pre-set.

Onboarding — Confirm info

Address state

Step 1 of 3. Two-line rows (label on top, value below) for proper mobile tap targets (~68px each). Every row tappable → push to dedicated edit screen (or open DOB wheel). All fields editable.

Edit triggers

  • Name → s-stripe-onb-edit-name
  • Email → s-stripe-onb-edit-email
  • Phone → s-stripe-onb-edit-phone (country code + number)
  • Country → s-stripe-onb-edit-country (searchable list + warn re-verification)
  • DOB → dob-picker-sheet (canonical 3-wheel sheet)
  • Address → s-stripe-onb-edit-address

Address — mandatory

Stripe requires a business address for Custom accounts (tax forms — 1099 in US, equivalents in EU). The row is marked Required in yellow. Continue is disabled until filled.

  • Filled — auto from coach_profile (business address field if we add it, otherwise the coach's primary training location as a hint they can edit).
  • Empty — placeholder "Add your address" in tertiary color. Continue disabled. Tap row → fill it in.

Hidden fields (handled by backend, not shown to user)

  • business_type: individual — hardcoded server-side. Every coach is an individual sole prop unless we add a company toggle later.
  • mcc: "7997" — Membership Clubs / Health & Fitness Services. Hardcoded for all coaches.
  • url — auto from coach_profile.social_link if present, otherwise null.
  • product_description — auto from coach_profile.bio if present, otherwise null.

All edits write back to the local auto snapshot. On Continue the merged payload is sent to PATCH /coach/stripe-onboarding/individual. Name + email + phone + DOB + address are also synced back to coach_profile (single source of truth — fixing them in Stripe context fixes them everywhere).

Onboarding — Verification

Step 2 of 3. Document type segmented control at top (Passport = 1 tile, ID / Driver's license = 2 tiles front+back) + always-visible info banner + single Continue (no Skip).

Document type

Why no Skip button

"Skip for now" + "Continue" both did the same thing — false choice. Instead: keep Continue, use the banner to explain the consequence upfront. User makes one informed call.

  • Upload tile turns teal outline + checkmark when image captured.
  • Continue is always enabled (no gating on upload state).
  • If nothing uploaded → s-stripe on return shows Connected · action (yellow banner).
  • If uploaded → s-stripe on return shows Connected · verifying (blue banner).

Camera-only capture (not gallery)

In production, tap on upload tile launches Stripe Identity SDK → opens system camera (UIImagePickerController in .camera mode on iOS, equivalent on Android). Not a gallery picker — Stripe wants a fresh photo to prevent uploaded edited/stale documents. SDK does the framing overlay + auto-detects edges + handles compression before sending to Stripe Verification API directly (the file never hits our backend). Our backend just records the verification.document.front/back field IDs Stripe returns.

Passport vs ID/license behavior: Passport mode hides the second tile entirely (single page document). ID/license shows both tiles — back is required for most country IDs, optional only for US passports (which aren't passports in our switch anyway). Backend doesn't care about this UI distinction — it just receives 1 or 2 photos and forwards.

Onboarding — Payout destination

Type

Step 3 of 3. Same Bank ↔ Debit card segmented control as the post-onboarding Add method screen — consistency keeps coaches from learning two slightly different UIs.

Why Bank is the default

Most coaches just want their money. Bank is free and reliable; card is opt-in for speed with a fee. Defaulting to Bank keeps the path of least resistance simple — the hint line under the control names this ("Recommended" tag on Bank, "1% Stripe fee" on Card) so the choice is clear without pushing card.

API

POST /coach/stripe-onboarding/external-account body:

  • Bank: {type: "bank_account", iban, country, currency, swift_bic?}
  • Card: {type: "card", number, exp_month, exp_year, cvc}

Followed by POST /coach/stripe-onboarding/accept-tos. Both must succeed; rollback on partial fail. T&C copy adapts noun ("account" vs "card") via the segmented control.

Country gating (same as Add method): Stripe only allows card external accounts in countries with Instant Payouts capability (US, UK, EU incl. Spain). If coach's country is unsupported, backend returns 400 → frontend hides the Card tab + shows toast. v1 assumes the coach is in a supported country (Spain test case).

Add payout method

Type

Unified form for bank and debit card. Segmented control at top switches between them. Fields swap, holder + country shared. Optional "Set as default" checkbox below.

Differences shown to user

  • Bank — SEPA/IBAN transfer, 1–2 business days, free. Fields: IBAN + SWIFT/BIC (optional).
  • Card — Instant Payouts (under 30 min), 1% Stripe fee per payout. Fields: Card number + Expiry + CVC. Info banner reminds that only debit cards work (credit not supported).

API

POST /coach/stripe-onboarding/external-account with body:

  • Bank: {type: "bank_account", iban, country, currency}
  • Card: {type: "card", number, exp_month, exp_year, cvc}

Card-as-payout is country-gated. Stripe enables it for US, UK, and most EU (incl. Spain, FR, DE, IT). Backend checks coach's account country against Stripe's instant_payouts_supported list and hides the Card tab if not supported. For v1 we don't expose the toggle gating in UI — the form just rejects on submit with a friendly error.
