Refer a coach (referral program)

Coach-only referral program — grow the platform, earn a reward. Distinct from shared/connect.html (in-person QR connect) and from the Clients-tab contacts import (mass-invite as CRM clients). One scrolling screen, sections not tabs per feedback_tabs_vs_sections. Dark by default (coach).

⚠️ Reward = “1 free month when they subscribe” is a fixed PLACEHOLDER. Reward tiers / final copy / how earned months are displayed are TBD — a later product decision. Prototype just proves the flow + funnel.

Sections (top → bottom)

  • Offer hero — gift + “Invite a coach — get 1 free month when they subscribe”. Value stated up front (Uber / Cash App / Revolut pattern).
  • Your referral link — OneLink 321.fit/i/{coach} + Copy + Share. Share opens the native drawer → mass send covered. No contacts multi-select here — that’s the Clients-tab import (project_crm_import_invite); we don’t triplicate the picker.
  • Funnel — Joined · Subscribed · Free months. This is the coach’s OWN reward at a glance — never the referred coach’s private business numbers.
  • Recent invites — last 3, each: avatar + name + role/when + trailing status (Subscribed ✓ teal = reward earned · Joined neutral). Coach vs athlete shown in the meta line.
  • See all invites (N) → push to full list.

Coach vs athlete joiner

Both join via the same OneLink and both count as “joined” (attribution credit). Only a coach who subscribes triggers the reward — athletes are free (project_business_model), so an athlete joiner shows Joined and never a reward badge.

Backend contract

Extends referrals from project_invite_a_coach — additive per feedback_backward_compat_endpoints:

  • GET /coach/me/referral-link → { url, token }
  • GET /coach/me/invites?limit=20&cursor=… → joined list; each item gains role (coach|athlete) + reward_status (joined|subscribed) + joined_at.
  • Signup accepts referral_token → creates row status: joined.
  • Coach-subscription hook flips reward_status → subscribed, credits inviter +1 month, fires push (REFERRAL_SUBSCRIBED).
  • reward_status, role, funnel counts are new additive fields — a plain joined-list still works without them.

Reward crediting logic (how free months apply to the subscription, tiers, caps, fraud guards) is deferred — not in this prototype. Funnel + badges are display-only until that lands.
