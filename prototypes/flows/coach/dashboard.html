Dashboard

Answers “what do I need to know right now?” — not an analytics panel. Deep financial view lives in Earnings, full agenda in Calendar.

  • Greeting + summary — time-of-day greeting, inline count of today’s sessions & earnings
  • Next Session — featured card, relative time in teal (“In 45 min”), tap → event detail
  • Action cards — Pending requests / Cash to collect / Sessions to review. Each card hidden when count = 0
  • This week — big amount + trend pill (up/down/flat) + planned earnings + embedded Card/Cash split. Tap → Earnings
  • Activity (Signals) — latest review + new clients this week. Hidden when nothing new

Navigation: Home tab root. Bottom nav 5 items. No back chevron. Header = “Home” + notification bell.

Tap targets:

  • Next Session → event detail sheet (unified cal-event-sheet in state Planned)
  • Pending requests → Clients tab, Requests segment
  • Cash to collect → Clients tab (filtered: outstanding cash)
  • Sessions to review → Calendar (filtered: Review state)
  • This week → Earnings
  • Activity rows: review → Profile reviews section; new clients → Clients tab

Data dependency: GET /coach/dashboard response needs these fields (extending current spec):

  • nextEvent — (exists) EventModel
  • pendingRequestsCount — (exists)
  • cashToCollect — new: {count, total, currency}
  • sessionsToReviewCount — new: Int
  • todaySummary — new: {sessionCount, totalValue}
  • weekEarnings — new: {earned, plannedAdditional, bookedCount, cardTotal, cashTotal, cashClientCount, trendVsLastWeek}
  • signals — new array: [{type, ...}] with latestReview + newClientsThisWeek

States (9 total — full coach lifecycle)

  • Default — typical active coach, all blocks populated + Tier 2 tip at bottom
  • New — Tier 1 onboarding wizard (6 steps) with progress bar. Collapsible. Nothing else shown — setup gates everything
  • Under review — wizard done, waiting approval (up to 24h). Teal-bordered banner + 3 Optional boosts (Stripe / Hours / Video). No Next Session / Earnings (nothing to show)
  • Ready — approved, no history yet. Empty Next Session with Invite + Share CTAs + CRM tip + Tier 2 Stripe tip
  • Idle — approved, has history, 0 upcoming. Empty-next copy shifts to “Nothing scheduled / Invite / See recent clients” + Tier 2 Available hours tip
  • Quiet day — no sessions today, next is tomorrow
  • All zero — active coach, nothing to act on. No tip (clean inbox is its own reward)
  • Loading — skeleton per section, shimmer animation
  • Error — inline banner at top + Retry + cached content faded 60%

Onboarding tiers

  • Tier 1 (required for approval) — 6-step wizard: phone, sports, photo, about, location, first session. Gates coach visibility in search. Auto-hides after approval.
  • Tier 2 (optional, impact-driving) — Stripe, Available hours, Video intro. Shown as single rotating tip card in Ready/Idle/Default. Dismissable. Under-review state shows all 3 as “Optional boosts” since coach is idle anyway.
  • Rules: never show both tiers at once. Max 1 tip card per state. Dismissed 3× → hide forever. Tip auto-removes when its condition is met (e.g., Stripe connected → Stripe tip never returns).

Next Session empty variant — one component, copy adapts by backend flag hasHistory:

  • hasHistory = false → “No sessions booked yet” / “Share your profile to get your first client” / CTAs: Invite a client + Share profile
  • hasHistory = true → “Nothing scheduled” / “Invite a client or reach out to recent ones” / CTAs: Invite a client + See recent clients

Copy rules

  • Sentence case everywhere (“Pending requests” not “Pending Requests”)
  • Relative time for next session: “In 45 min”, “In 2h”, “Tomorrow”, “Thu 15 Apr”
  • Trend pills: “€80 up” → icon + value. Flat = neutral copy
  • Plurals explicit: “1 pending request”, “3 pending requests”

Athlete dashboard is a separate build — simpler (next session + requests + balance), no revenue breakdown.

Sessions to review

Triage queue for sessions in Review state — events that ended but coach hasn’t marked complete or missed yet.

Why a dedicated list, not calendar: for N > 1 a calendar view forces hunting; the queue presents all pending reviews oldest-first for batch handling. For N = 1 we still land here (consistency > saving one tap).

  • Grouping: by date, oldest first (most urgent at top)
  • Card: avatar + name + sport/duration, date/time line, location line, money + payment type, “Ended N ago” timestamp
  • Inline actions: Mark complete (primary brand gradient) + Missed (low outlined red — per 4-tier destructive system, low because it’s a judgment call not data loss)
  • Tap card body → event detail sheet for full context (notes, past stats) before deciding
  • After tap: card fades + collapses, snackbar “Marked complete” / “Marked missed” with Undo
  • After last card handled: list transitions to Empty state; action card on dashboard hides

Entry points

  • Dashboard → action card “N sessions to review”
  • (Future) calendar badge on dates with events in Review state

States

  • Filled — typical 2–3 items across recent days
  • Single — 1 item queue (same screen, consistent UX)
  • Empty — all caught up, illustration + explanation
  • Loading — skeleton cards on first fetch

Missed styling rationale: low-severity destructive (outlined red) — marking missed is coach’s judgment, reversible within retention window. Not medium (tinted) because no other-user impact at this moment; not high because no data loss.

Backend: needs GET /coach/events?status=review or equivalent filtered endpoint. Bulk actions (select-all → mark complete) deferred until user feedback warrants it.
