Template detail — Group

Tapping a template in My Sessions now lands here, not in the edit form. Editing settings and managing what the template spawned are two different jobs — the old screen did both and buried the second one under a form.

  • Summary card reuses the list-card shell (same gradient header per type) so the object reads continuous from list → detail. Everything the coach set lives there read-only + one Edit button.
  • Stats strip — same three columns on all three types (upcoming / booked / earned). One component, type-specific numbers.
  • Events — segmented Upcoming | Past. Recurring placements render as a rule head + 3 nearest instances; one-off placements stand alone.
  • Exceptions always surface — moved / skipped / zero-signup dates get an amber row even if they sit 5 weeks out. Normal dates stay collapsed.
  • Footer CTA Schedule dates → the existing scheduling flow (invite.html?mode=schedule).
Why the list is finite

Ongoing ≠ infinite

A weekly placement with Ends: Ongoing is a rule. The engine materialises occurrences 60 days ahead, rolling daily (canon: group-training decisions — matches the Google-sync window). So the list always has a bottom, and the sub-line says so out loud: “Ongoing · next 60 days”. Without that label a coach reads the last row as the end of the series.

Three levels, not two

Template (what I run: price, duration, capacity) → Series/placement (when it repeats) → Event (one date, its roster and money). Each level owns its own edits — which is why the apply-scope picker moved off the template form and onto the series.

Never-scheduled state

A freshly created template has zero placements. Athletes can’t book it at all, so the empty state says that explicitly rather than showing a blank list.

API

GET /coach/training-sessions/{id}/ · GET /coach/training-events/?session_id={id}&from=&to= grouped by recurrence_pattern.

Template detail — Personal

Same shell, different spawn. A personal template has no standalone events — it produces bookings with a specific athlete, so the lower section is a people list, not a date list.

  • Bookings — avatar + name + when + payment badge (Paid / Cash due / Awaiting). Tap → the event drawer on the calendar.
  • Clients using this session — avatar stack tile → CRM filtered to this template. Answers “is this offer working?” at a glance.
  • Past — recent bookings individually, older months collapsed to a summary row (12 sessions · 5 clients · €600).
  • Footer CTA Book with a client enters the canonical booking flow at step 2 — the session is already picked, so only athlete + time are left (canon order session → athlete → time).
Coach

Template detail — Self-paced

Self-paced has no dates at all, so the “what did this template spawn” section becomes athletes and their progress. Ordered by what the coach owes, not chronology.

  • Needs your plan — amber rows: athletes who paid and are waiting for the workout to be built. This is a debt, so it sits at the top.
  • In progress — completion bar (3 of 8 workouts), plus “submitted for review” when the ball is back in the coach’s court.
  • Completed collapses to a single tile — archive, not work.
  • Rows deep-link into the existing builder (shared/self-paced.html → queue / setup / review) instead of duplicating it here.
  • Stats strip reads to build / sold / earned — same component, self-paced vocabulary.

Location and cash payment are absent by design — self-paced is online-only, paid from the athlete’s balance.

Series detail

The full date list for one recurring placement — opened from the series head’s “17 dates”. The rule card at the top is the object being managed; the rows below are what it generated.

  • Month groups + lazy loading. Bounded by the 60-day generation window, with a footnote explaining why the list ends — and that new dates appear on their own.
  • Quick-chip axis: All / Needs attention. One axis only (canon: ledger filter pattern) — the exceptions are the only filter a coach actually asks for.
  • Exception badges: Moved (blue — time override), Skipped (amber — conflict auto-skip at generation), cancelled rows dimmed. Everything else is a plain row.
  • Edit schedule opens the scope sheet here: This and all following / All dates — the Google-calendar convention, and the correct home for a scope question about dates.
  • ⋯ carries Add a date and destructive Cancel series.
Scope moved off the template

Before

The template edit form asked “future events only / all upcoming” for every impactful change, including schedule-shaped ones — while the dates themselves lived in a section on that same form.

Now

Settings changes (price, duration, location) keep their scope sheet on the edit form, because they genuinely fan out to already-generated events. Schedule changes (days, time, ends) get their scope on the series, where the coach can see the affected dates while deciding.

Edit template (cleaned)

Reached from the summary card’s Edit. Now a pure settings form — three things left it:

  • Training type is read-only. It decides capacity, location, payment methods and the whole booking model; switching it on a template with 12 events and 47 registrations isn’t an edit, it’s a different object. Shown as a locked row + hint, with Duplicate as the escape hatch.
  • Scheduled dates section removed — it lives on the detail screen, where it can actually breathe (series grouping, exceptions, past).
  • Header trash removed — deleting the template is an action on the object, so it sits in the detail’s ⋯ menu, away from the form’s primary Save.
  • Kept: prefilled fields, impactful-change scope sheet on Save, participant-notification warning.
