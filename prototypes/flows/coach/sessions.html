Create Training Session

Unified template form for personal and group — a reusable definition, no dates/times. Group-only fields (max/min participants) hide/show with animation on type toggle.

  • Personal / Group toggle — hides/shows participant fields
  • Price label changes: "Price" vs "Price per participant"
  • No schedule here — dates, times & recurrence are picked later when the coach schedules this template on the calendar (see Schedule flow)
Full behavior spec

Template vs schedule (new model)

A training session is now a pure template: name, sport, location, duration, price, participants, payment. It carries no recurrence, days, or time. Scheduling is a separate step (calendar FAB → "Schedule training" → pick template → drag onto time-grid → recurrence drawer). One template → many placements (e.g. Tue 12:00 and Fri 17:00).

Prefilled defaults

Sport: first from profile. Location: first address. Type: Personal. Payment: Cash + Card. Max: 10, Min: 3.

Validation (Errors state)

Save always active. On tap Save: validates name, duration, price. Red border + red label on empty fields (all at once). Auto-scroll to first error. Snackbar: "Please fill in required fields" for 2.5s. Error styles auto-clear after 3s so user can focus and retype. Re-typing in a field does NOT auto-clear — only Save re-validates.

Location picker

Tap Location field → pushes to Training Locations screen in select mode. Shows all in-person + online locations. Tap = select + pop back. Supports both physical gyms and online meeting links.

API

POST /coach/training-sessions/ (create) · PUT /coach/training-sessions/{id}/ (edit).

Coach

My Training Sessions

Two tabs via a segmented control: Sessions (templates) and Packages (prepaid packs). Packages were moved out of the template form into their own flow — a pack is a separate credit-ledger object, not a template field.

  • Sessions tab: tap card → edit template. Header "+" → create new session.
  • Packages tab: cards grouped by base session, tiers listed inside. Tap card body → package Overview; tap the footer ("18 sold · 6 active" / "running low") → jumps straight to the Buyers tab. Header "+" → pick a session → editor.
  • Athlete side unchanged — packs are discovered session-first (buy strip on the session card), no separate athlete packages tab.
States & behavior

Empty state

Coach has 0 templates (fresh signup or all deleted). Illustration + title + subtitle + primary "Create session" CTA. CTA pushes to s-create. Bottom navbar still visible.

Loading state

Shown during GET /coach/training-sessions/. Skeleton cards (3 placeholders) with shimmer. Prevents layout shift when data arrives.

Error state

Network/server error → inline retry card replaces list (cross-cutting pattern, #8).

API

GET /coach/training-sessions/ — returns template list.
DELETE /coach/training-sessions/{id}/ — with cascade warning if used in scheduled events.

Coach

Template detail — Group

Tapping a template in My Sessions now lands here, not in the edit form. Editing settings and managing what the template spawned are two different jobs — the old screen did both and buried the second one under a form.

  • Summary card reuses the list-card shell (same gradient header per type) so the object reads continuous from list → detail. Everything the coach set lives there read-only + one Edit button.
  • Events — segmented Upcoming | Past. Recurring placements render as a rule head + 3 nearest instances; one-off placements stand alone.
  • Exceptions always surface — moved / skipped / zero-signup dates get an amber row even if they sit 5 weeks out. Normal dates stay collapsed.
  • Footer CTA Schedule dates → the existing scheduling flow (invite.html?mode=schedule).
Why the list is finite

Ongoing ≠ infinite

A weekly placement with Ends: Ongoing is a rule. The engine materialises occurrences 60 days ahead, rolling daily (canon: group-training decisions — matches the Google-sync window). So the list always has a bottom, and the sub-line says so out loud: “Ongoing · next 60 days”. Without that label a coach reads the last row as the end of the series.

Three levels, not two

Template (what I run: price, duration, capacity) → Series/placement (when it repeats) → Event (one date, its roster and money). Each level owns its own edits — which is why the apply-scope picker moved off the template form and onto the series.

Never-scheduled state

A freshly created template has zero placements. Athletes can’t book it at all, so the empty state says that explicitly rather than showing a blank list.

API

GET /coach/training-sessions/{id}/ · GET /coach/training-events/?session_id={id}&from=&to= grouped by recurrence_pattern.

Template detail — Personal

Same shell, different spawn. A personal template has no standalone events — it produces bookings with a specific athlete, so the lower section is a people list, not a date list.

  • Bookings — avatar + name + when + payment badge (Paid / Cash due / Awaiting). Tap → the event drawer on the calendar.
  • Clients using this session — avatar stack tile → CRM filtered to this template. Answers “is this offer working?” at a glance.
  • Past — recent bookings individually, older months collapsed to a summary row (12 sessions · 5 clients · €600).
  • Footer CTA Book with a client enters the canonical booking flow at step 2 — the session is already picked, so only athlete + time are left (canon order session → athlete → time).
Coach

Template detail — Self-paced

Self-paced has no dates at all, so the “what did this template spawn” section becomes athletes and their progress. Ordered by what the coach owes, not chronology.

  • Needs your plan — amber rows: athletes who paid and are waiting for the workout to be built. This is a debt, so it sits at the top.
  • In progress — completion bar (3 of 8 workouts), plus “submitted for review” when the ball is back in the coach’s court.
  • Completed collapses to a single tile — archive, not work.
  • Rows deep-link into the existing builder (shared/self-paced.html → queue / setup / review) instead of duplicating it here.

Location is absent by design — self-paced has nowhere to be. Cash is allowed like on any other type: the request still goes to the coach to accept or decline, and a coach who just trained someone in person may well take the money by hand. Card pays from the athlete’s balance at booking; cash is collected later, exactly as for a personal session.

Coach

Series detail

The full date list for one recurring placement — opened from the series head’s “17 dates”. The rule card at the top is the object being managed; the rows below are what it generated.

  • Month groups + lazy loading. Bounded by the 60-day generation window, with a footnote explaining why the list ends — and that new dates appear on their own.
  • Quick-chip axis: All / Needs attention. One axis only (canon: ledger filter pattern) — the exceptions are the only filter a coach actually asks for.
  • Exception badges: Moved (blue — time override), Skipped (amber — conflict auto-skip at generation), cancelled rows dimmed. Everything else is a plain row.
  • Edit schedule opens the scope sheet here: This and all following / All dates — the Google-calendar convention, and the correct home for a scope question about dates.
  • ⋯ carries Add a date and destructive Cancel series.
Scope moved off the template

Before

The template edit form asked “future events only / all upcoming” for every impactful change, including schedule-shaped ones — while the dates themselves lived in a section on that same form.

Now

Settings changes (price, duration, location) keep their scope sheet on the edit form, because they genuinely fan out to already-generated events. Schedule changes (days, time, ends) get their scope on the series, where the coach can see the affected dates while deciding.

Edit template (cleaned)

Reached from the summary card’s Edit. Now a pure settings form — three things left it:

  • Training type is read-only. It decides capacity, location, payment methods and the whole booking model; switching it on a template with 12 events and 47 registrations isn’t an edit, it’s a different object. Shown as a locked row + hint, with Duplicate as the escape hatch.
  • Scheduled dates section removed — it lives on the detail screen, where it can actually breathe (series grouping, exceptions, past).
  • Header trash removed — deleting the template is an action on the object, so it sits in the detail’s ⋯ menu, away from the form’s primary Save.
  • Kept: prefilled fields, impactful-change scope sheet on Save, participant-notification warning.

Replaces the old edit form: training type is read-only, scheduled dates and Delete live on the detail screen.

Choose a session

Step 1 of package creation. A pack is always based on one session, so the coach picks the base template first. Reuses the My Sessions card style as a selectable picker.

  • Tap a session → package editor opens with that session preselected (its single price feeds the discount math)
  • Grouped by type (Personal / Group / Self-paced) — packs work on all three
  • Back → returns to the Packages tab
Coach

Package tier edit

Add or edit one tier of a package — a pack size and what it costs. Opened from the Overview card's pencil (edit) or "+ Add package tier" (add). Isolated to that single tier: the other tiers are untouched.

  • Screen, not a bottom sheet. The € total is a typed field — a keyboard over a sheet buries both the live math and the Save button, and the deep-linked Remove disappears entirely. Focused input → pushed screen (same rule as OTP entry and the template form).
  • Back = cancel, footer Save tier commits — nothing is written to the tier card until then. This also fixes the create flow's two competing Saves: this screen saves a tier, the package screen creates the package.
  • Base session row repeated at the top (read-only) — the €25-single price is what the discount is measured against, so it must stay visible while typing.
  • Live math under the price: €/session + save % vs the single price — the coach is tuning a discount ladder, not just entering a number.
  • Header trash removes the tier (edit mode only, hidden on the last tier — a pack needs ≥1 tier) → confirm sheet. Same placement as the package screen's delete, so destructive never sits next to the footer's primary CTA. Existing buyers of that size keep their credits.
Coach

Package detail

In edit/detail mode a segmented [ Overview | Buyers ] splits defining the pack from managing its customers. In create mode (from Pick) there are no buyers yet, so the tabs + stats are hidden — just Overview.

  • Overview is view-first. Under the base session row, tiers as read-only info cards (sessions · €total · €/ea · save% · N sold, leader tagged "Best seller"). Editing is per-tier on its own screen: a card's pencil or "+ Add" pushes Package tier edit — it touches only that one tier, not the others. Create mode has a "Create package" footer to finalise; detail saves each tier on the tier screen (no bulk footer). Max 3 tiers (market avg 2–3; more = choice paralysis); last tier's Remove is hidden.
  • Buyers — every athlete holding this pack + remaining sessions (progress bar). Running-low rows (≤1 left / used up) turn amber and get an inline Offer renewal (→ "Offer sent"); a bulk "renewal → all running low" sits at the bottom (→ "Renewal sent"). Zero state when nothing sold yet. Card footer "18 sold · 6 active" deep-links straight here.
  • No expiry — packs never expire (locked model — keeps refunds simple, defuses gift-card-expiry legal risk), so there's no expiry field.
  • Header trash deletes the pack; existing credit holders keep their sessions (refund is the coach's call — the athlete is told so at purchase). Payment axis (cash/card) isn't set here — both always allowed; a cash pack is bookable from purchase (no redeem gate) and only carries a "Pending payment" marker until the coach marks it received.
Why a separate flow

Decoupled from the template

A package is a separate credit-ledger object (N credits of session X), not a template property. Keeping its editor off the template form means editing a pack never drags the whole session form along, and the template form stays lean.

Athlete symmetry

Athletes discover packs session-first (a "Save with a 5-pack" strip on the session card in the catalog) — no separate athlete packages tab. Coach grouping (card = session → its tiers) mirrors that mental model.
