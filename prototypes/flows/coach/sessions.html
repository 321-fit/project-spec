Create Training Session

Unified template form for personal and group — a reusable definition, no dates/times. Group-only fields (max/min participants) hide/show with animation on type toggle.

  • Personal / Group toggle — hides/shows participant fields
  • Price label changes: "Price" vs "Price per participant"
  • No schedule here — dates, times & recurrence are picked later when the coach schedules this template on the calendar (see Schedule flow)
Full behavior spec

Template vs schedule (new model)

A training session is now a pure template: name, sport, location, duration, price, participants, payment. It carries no recurrence, days, or time. Scheduling is a separate step (calendar FAB → "Schedule training" → pick template → drag onto time-grid → recurrence drawer). One template → many placements (e.g. Tue 12:00 and Fri 17:00).

Prefilled defaults

Sport: first from profile. Location: first address. Type: Personal. Payment: Cash + Card. Max: 10, Min: 3.

Validation (Errors state)

Save always active. On tap Save: validates name, duration, price. Red border + red label on empty fields (all at once). Auto-scroll to first error. Snackbar: "Please fill in required fields" for 2.5s. Error styles auto-clear after 3s so user can focus and retype. Re-typing in a field does NOT auto-clear — only Save re-validates.

Location picker

Tap Location field → pushes to Training Locations screen in select mode. Shows all in-person + online locations. Tap = select + pop back. Supports both physical gyms and online meeting links.

API

POST /coach/training-sessions/ (create) · PUT /coach/training-sessions/{id}/ (edit).

Coach

My Training Sessions

Two tabs via a segmented control: Sessions (templates) and Packages (prepaid packs). Packages were moved out of the template form into their own flow — a pack is a separate credit-ledger object, not a template field.

  • Sessions tab: tap card → edit template. Header "+" → create new session.
  • Packages tab: cards grouped by base session, tiers listed inside. Tap card body → package Overview; tap the footer ("18 sold · 6 active" / "running low") → jumps straight to the Buyers tab. Header "+" → pick a session → editor.
  • Athlete side unchanged — packs are discovered session-first (buy strip on the session card), no separate athlete packages tab.
States & behavior

Empty state

Coach has 0 templates (fresh signup or all deleted). Illustration + title + subtitle + primary "Create session" CTA. CTA pushes to s-create. Bottom navbar still visible.

Loading state

Shown during GET /coach/training-sessions/. Skeleton cards (3 placeholders) with shimmer. Prevents layout shift when data arrives.

Error state

Network/server error → inline retry card replaces list (cross-cutting pattern, #8).

API

GET /coach/training-sessions/ — returns template list.
DELETE /coach/training-sessions/{id}/ — with cascade warning if used in scheduled events.

Edit Training Session

Template detail + edit. Same fields as create, prefilled — plus a Scheduled dates section (this template's live placements) unique to edit mode. A freshly created template has no placements until scheduled → empty state.

  • Scheduled dates — lists each placement of this template (recurring series + one-off "Special" events). Tap a row → manage on calendar.
  • Schedule new dates CTA → hands off to the scheduling flow (invite.html?mode=schedule&origin=s-edit) → drag-drop time-grid → recurrence drawer.
  • Non-impactful edits (name, price, max): apply silently.
  • Impactful edits (duration, location, price): scope picker (future only / all upcoming) + participant warning.
  • Delete (header trash): keep existing events vs cancel-all-and-refund.
Coach

Choose a session

Step 1 of package creation. A pack is always based on one session, so the coach picks the base template first. Reuses the My Sessions card style as a selectable picker.

  • Tap a session → package editor opens with that session preselected (its single price feeds the discount math)
  • Grouped by type (Personal / Group / Self-paced) — packs work on all three
  • Back → returns to the Packages tab
Coach

Package detail

In edit/detail mode a segmented [ Overview | Buyers ] splits defining the pack from managing its customers. In create mode (from Pick) there are no buyers yet, so the tabs + stats are hidden — just Overview.

  • Overview is view-first. Under the base session row, tiers as read-only info cards (sessions · €total · €/ea · save% · N sold, leader tagged "Best seller"). Editing is per-tier via a drawer: a card's pencil or "+ Add" opens a focused bottom sheet (sessions stepper + € total + live math) with explicit Save tier (+ Remove when editing) — it touches only that one tier, not the others. Create mode has a "Create package" footer to finalise; detail saves each tier on drawer Save (no bulk footer). Max 3 tiers (market avg 2–3; more = choice paralysis); last tier's Remove is hidden.
  • Buyers — every athlete holding this pack + remaining sessions (progress bar). Running-low rows (≤1 left / used up) turn amber and get an inline Offer renewal (→ "Offer sent"); a bulk "renewal → all running low" sits at the bottom (→ "Renewal sent"). Zero state when nothing sold yet. Card footer "18 sold · 6 active" deep-links straight here.
  • No expiry — packs never expire (locked model — keeps refunds simple, defuses gift-card-expiry legal risk), so there's no expiry field.
  • Header trash deletes the pack; existing credit holders keep their sessions (refund is manual). Payment axis (cash/card) isn't set here — both always allowed; cash packs activate when the coach marks payment received.
Why a separate flow

Decoupled from the template

A package is a separate credit-ledger object (N credits of session X), not a template property. Keeping its editor off the template form means editing a pack never drags the whole session form along, and the template form stays lean.

Athlete symmetry

Athletes discover packs session-first (a "Save with a 5-pack" strip on the session card in the catalog) — no separate athlete packages tab. Coach grouping (card = session → its tiers) mirrors that mental model.
