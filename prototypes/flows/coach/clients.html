Coach

Clients

CRM-style client list. Root tab screen (no back arrow).

  • "+" icon → calendar-style drawer with 4 options (Create profile / Import from contacts / Invite to app / Invite to training), each with a description line
  • "€50 owed" red badge (Mark S.) — client has unpaid cash session
  • Deleted accounts are NOT in this active list — when an athlete deletes their account the relationship is effectively dead, so it surfaces under Archived & Blocked → Blocked (terminal, no unblock), not here. History stays intact.
  • "CRM" badge (Marta V.) — coach-created contact without app account. Teal-tinted pill, normal avatar color. Coach tracks sessions/cash manually; can later Invite to app to upgrade.
  • Tap client → Client Detail

"+" drawer actions:
• Create profile → CRM form (New Client screen)
• Import from contacts → bulk-add from phone book → Import Done → mass invite (see Import Contacts annotation)
• Invite to app → native share drawer with the coach's OneLink. No intermediate screen.
• Invite to training → select training template, then a deep link with the event attached.

Empty: fresh coach — «Add first client» CTA opens the same add-client sheet. Loading: 4 skeleton rows during initial fetch. Archived row at bottom is hidden when 0 archived+blocked — appears only after first use.

Coach

Client Detail

Full athlete profile from coach's perspective.

  • Header: avatar, name, location, sport chips — always visible (instant header, reused from list)
  • Stats card: Sessions | Upcoming | Revenue | Owed. Fresh = all zeros in muted color.
  • Pending Payments: section appears only when unpaid exists (hidden at 0). Tap Manage on a pending card → bottom-sheet drawer with 2 options: Mark as paid (Owed↓ + Revenue↑) or Waive payment (Owed↓ only, €0 income, status payment_waived, silent to athlete). Both terminal. Snackbar confirms; card fades; badge decrements. Last card cleared → whole section collapses. Same drawer pattern as balance.html#s-txn-cash Manage payment.
  • Upcoming Sessions: carousel of cards; when empty → outline card with Schedule training CTA
  • Notes: outline card (transparent bg + divider border). Tap anywhere opens full-screen editor. Empty variant shows pencil + Add notes.
  • Training History → row hidden when 0 sessions
  • ⋯ menu (header right): floating iOS UIMenu pattern. Menu items scoped per client state:
    • Normal → Schedule training / Edit / Archive / Block
    • Deleted → Archive only (can't act on a gone account)
    • CRM → Invite to app / Invite to training / Edit / Archive (no Schedule — no push target; no Block — not in app anyway)
  • Status banners at top: Archived (gray, Restore) / Blocked (red, Unblock) / Deleted (gray, date-stamped, no action).
  • CRM indicator: small teal CRM pill inline next to name (same pattern as in Clients list). No banner — less visual noise. «Invite to app» action lives in ⋯ menu.

Schedule training (⋯ menu + fresh-state Upcoming CTA) → navigates to invite.html?mode=schedule&origin=s-client-detail. Reuses Select Training + Date/Time screens with Request-badge review instead of Invitation-badge. Send Request → back to Client Detail.

Client History

Full training history with athlete.

  • All past events: name, date/time, location, price, status
  • Completed + Paid: green label
  • Cancelled: red label, price struck through
  • Sorted newest first

Empty: brand-new client with 0 past sessions — no CTA (coaches initiate training from Client Detail, not here).

Coach

Archived & Blocked

List of clients removed from active Clients tab — by archive (soft) or block (hard).

  • Per-tab zero states — each tab empties independently (e.g. you have blocked clients but none archived → Archived tab shows its own empty state, Blocked still lists). Toggles above flip each tab + its count; no CTA (you archive/block from Client Detail, not here).
  • Segmented tabs: Archived / Blocked with counts
  • Muted cards (opacity avatar) — signals inactive status
  • Restore / Unblock buttons: single-tap (no confirm) → snackbar feedback
  • Tap card → Client Detail with status banner (see banner preview in Client Detail annotation)
  • Archive = soft, reversible, athlete unaffected — a new request brings them back
  • Block = silent shadow-ban, coach invisible in athlete's search, upcoming sessions untouched
  • Deleted badge (Karl L.) — athlete deleted their account. Surfaces in the Blocked tab (deleted ≈ blocked: relationship is dead). Terminal — no unblock/restore action (nothing to restore; account is gone). History stays intact. Removed from the active Clients list.

Entry: "Archived & Blocked" row at bottom of Clients list (iOS Mail "Trash" pattern).

Coach

Client Notes Editor

Full-screen editor for coach's private notes about an athlete. Same pattern as About Me editor — Cancel / title / Save header, contenteditable body, no character counter.

  • Opens from Notes card on Client Detail (tap whole card — filled or empty variant)
  • Accumulating journal: injuries, preferences, payment habits, personal reminders
  • No length limit — notes grow over months of coaching
  • Keyboard auto-opens; Save pops back to Client Detail

Distinct from event note (group training, per-session, 200 char limit) — client notes are long-lived and persistent.

Coach

Create Client

CRM card for athletes without app account.

  • First name — required. Last name — optional (a contact / import may be first-name-only; backend allows a name with no last name).
  • Phone number — optional; if filled validates phone format. Email removed — phone is the single match key for auto-linking when they join (email-fallback match deprecated).
  • Sport — dropdown from coach's sports
  • Notes — tap opens full-screen editor (injuries, preferences)

Validation: tap Create Client → red border + red label on missing/invalid fields (all at once) + auto-scroll to first error + snackbar «Please fill in required fields» for 2.5s. Error styles auto-clear after 3s so user can retype. Mirrors Create Session pattern.

Created athlete appears in Clients list with a teal CRM pill. Coach can track sessions/payments.

Coach

Import from contacts

Bulk-add clients from the phone address book. Opened from the Add-client drawer → OS asks for Contacts permission.

  • Granted → brief loading (skeleton) while we read the address book + run a dedup/match pass against existing clients & app users (to tag Already a client / On 321Fit) → list.
  • Multi-select rows with search. Select all toggles every eligible contact.
  • Already a client → row disabled (no dupes).
  • On 321Fit (phone already matches an app user) → selecting it connects instantly (active app relationship, origin: auto_phone_match) instead of creating a CRM stub.
  • No phone (email-only contact) → still importable as CRM, but tagged — can't be invited or auto-linked (no phone key).
  • Import N → bulk-creates CRM records (origin: "import") → Import Done screen. Name parsed from the contact; last name optional for imports (a contact may be first-name-only).

Permission denied → explainer + Open Settings. We never message contacts automatically — sending is always coach-initiated via native share.

Coach

Import Done — invite all

Confirmation after a bulk import + the entry point to the mass invite.

  • Shows how many landed in CRM + how many are invitable (have a phone).
  • Invite all N → opens the native share drawer with the coach's personal OneLink (321.fit/i/{coach}?c=crm_import). Coach picks a channel (WhatsApp, Messages…) and broadcasts to everyone at once — a message from a known person, not a platform blast.
  • Attribution lives in the link: anyone who signs up through it is credited to the coach (referral analytics), regardless of channel. Per-contact linking happens via phone-match on signup — no per-contact tokens needed.
  • Not now → straight to Clients; contacts stay as CRM, invite anytime later from the client's ⋯ menu.

A coach gets a notification when an imported contact joins (via the link OR phone-match) — handled in the notifications catalog / Dashboard inbox, not here.
