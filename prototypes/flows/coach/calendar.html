Coach Calendar

Behavior details

Day Navigation

Tap day on strip = instant switch. Swipe day strip = scroll. Swipe content left/right = page transition (Apple Calendar). Day strip auto-scrolls to selected day.

Month View Toggle

"April 2026 ▼" — tap title + chevron expands month grid. Day strip replaced by full month calendar. Tap a day = collapse back to day strip with selected day. Same component across all calendar screens (Coach, Athlete, Booking, Invite).

Drag & Drop

Long press event → event lifts, enters drag mode. Drag within same day only. Coach's own slot occupied → blocked. Unavailable zone → blocked. Participant conflicts → warning dialog "2 of 7 have conflicts. Move anyway?" Coach decides. Drop releases event at new time.

Day Strip Dots

p=personal (green), g=group (cyan), e=external (gray). At-a-glance overview.

Unavailable Zones

Hatched diagonal pattern = outside coach's available hours OR blocked by external calendar.

External Events

Imported from Google/Apple Calendar. Full-width, opacity 0.7, anonymized (title only).

Event Status System (6 states)

All non-Planned states share the same visual grammar: colored 10% bg tint + 1px perimeter + 3px left stripe + inline pill next to title. Pill appears inline (not absolute-positioned) — reads as part of the title. Colors map to semantic roles, not to coach/athlete roles.

  • Planned — teal (dark: teal-400 / light: teal-600) for personal, blue-400/600 for group. Base surface, no perimeter. No pill.
  • Request (incoming, pre-event) — yellow-600 perimeter + 10% yellow bg + yellow pill "Request". Athlete asked, coach needs to Accept/Decline.
  • Awaiting (outgoing, pre-event) — gray perimeter + subtle bg + gray pill "Awaiting". Coach sent request, waiting for athlete response. Muted because passive.
  • Review (post-event, unfinalized) — same yellow visual as Request. Event ended, coach hasn't opened Completion screen yet. Yellow because coach action needed — consistent lane with Request.
  • Missed — red-400 perimeter + 10% red bg + red pill "Missed". Explicit no-show or auto after N days without coach review.
  • Finished — base card at opacity 0.5, no pill, no perimeter. Past events that coach confirmed via Completion flow. Time + fade are sufficient signal; pill would be redundant.

Group events use only 4 of these states: Planned, Review, Missed, Finished. Request and Awaiting don't apply — group is a template, athletes join without approval.

Cancelled events disappear from calendar entirely (not a visible state). All visible statuses retained for 2 months, then archived.

API

GET {role}/training-events/?startDate&endDate
GET coach/training-events/allowed-hours/
PATCH {role}/training-events/{id}/change-status/

24-hour vertical timeline, 15-min grid snap.

  • Day strip — colored dots under days: 🟢 personal, 🔵 group, ⚫ external
  • Group events — cyan border + badge "7/10"
  • Personal events — green border + athlete name
  • Status pills — inline with title (not absolute-positioned). Yellow = Request or Review (coach action needed), gray = Awaiting (passive wait), red = Missed, no pill = Planned or Finished. See Behavior details for full system.
  • External events — gray, opacity, side-by-side with hatched unavailable zone
  • Unavailable hours — diagonal hatching overlay

Group Event Detail

Invite & deep-link

Share link

Generated on-demand via Appsflyer OneLink when coach taps Invite — not pre-generated for all future events. Short URL (321.fit/e/xK3aB) carries event_id in attribution params.

Rescheduled/cancelled events

Deep link resolves by event_id, so reschedule doesn't break it. If event cancelled before athlete opens → app shows "Event unavailable" and redirects to coach profile.

Caching

Backend caches short URL per event_id (1 Appsflyer call per event lifetime). Client caches per session.

"Ticket card" layout — compact summary + note + participants.

  • Ticket: badge + price, date/time, location, spots bar
  • Note to athletes — instance-only ad-hoc message (e.g. "bring a mat"). Tap to edit. Empty state = dashed "Add a note" CTA. Changes trigger push to all participants.
  • ⋯ menu (top-right) → Invite / Reschedule / Cancel training
  • Footer CTA → "Invite athletes" (primary) when spots available; "Complete Training" for past events
  • Tap participant → athlete profile (clients module)
  • Swipe left or × → remove with 5s Undo snackbar (batched for multiple, commits after 10s max)
  • Long press → quick actions sheet (Profile, Message, Remove)
  • Empty state (Empty toggle): no participants, no note, dashed CTA visible

Event Completion

Entry & flow

Entry point

Push notification after event end time: "Training ended. Tap to review and complete." Deep links to this screen.

Unpaid cash

Does NOT block completion. Stays as cash_pending record. Coach can see unpaid athletes in training history.

Post-training screen. Coach reviews payments and completes training.

  • Card participants: auto "Paid" badge, no action needed
  • Cash participants: checkbox, swipe right/left, long press
  • Payment summary: "4 paid · 1 unpaid"
  • Each row shows payment method (Card/Cash)
  • Complete Training → triggers Stripe transfers for card
