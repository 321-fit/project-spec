Coach Calendar

Behavior details

Day Navigation

Tap day on strip = instant switch. Swipe day strip = scroll. Swipe content left/right = page transition (Apple Calendar). Day strip auto-scrolls to selected day.

Month View Toggle

"April 2026 ▼" — tap title + chevron expands month grid. Day strip replaced by full month calendar. Tap a day = collapse back to day strip with selected day. Same component across all calendar screens (Coach, Athlete, Booking, Invite).

Drag & Drop

Long press event → event lifts, enters drag mode (.fit-timeline.dragging). Drag within same day only. Over any slot that won't take it — occupied, blocked, or outside available hours — the dragged tile turns .invalid (red tint + red perimeter + red text), the off-hours band deepens and its label steps aside, and the snackbar names the reason (“Outside your available hours”). The zone itself never turns red: flooding half the day with an error colour mid-drag is alarm without information and competes with the tile the coach is actually looking at. Same grammar as .fit-bk-sel.invalid in the booking grid. Drop is refused. Participant conflicts → warning dialog "2 of 7 have conflicts. Move anyway?" Coach decides. Drop releases event at new time.

Day Strip Dots

p=personal (green), g=group (cyan), e=external (gray). At-a-glance overview.

Off-hours vs Blocked zones

The grid is always a full 00:00–24:00 — day height never depends on availability, and the view auto-scrolls to the now-line (or to the first available hour) on open.

Off-hours (.fit-cal-offhours) = outside the coach's available hours. Flat tonal wash, full-bleed edge to edge (time gutter included) and no radius — an inset rounded band reads as an object lying on the day, full-bleed reads as a state OF the day. Hour labels stay on top, dimmed. Calm enough to cover 8+ hours without visual noise.

Every contiguous zone carries its own centered “Outside your hours” label — a fragmented availability day (06–10, 12–14, 18–20) explains itself wherever the coach lands. No time range in the text: the ruler on the left already says it, and the short phrase repeats across many segments without becoming noise. Zones under 32px drop the label (it wouldn't fit) and keep the wash.

Blocked (.fit-cal-blocked) = a slot inside working hours that is taken (external calendar, time off). Diagonal hatch — the hatch pattern is reserved for “busy” so it keeps exactly one meaning.

External Events

Imported from Google/Apple Calendar. Full-width, opacity 0.7, anonymized (title only).

Cross-role Events

A 321Fit event belonging to the user's OTHER role profile (e.g. Coach calendar showing a slot the user booked as an Athlete with another coach). Visually muted (opacity 0.75) with a dashed left stripe + small role tag in the corner to distinguish from external (which is solid stripe, no tag). Title shows sport name; meta line includes time and the OTHER party's name (e.g. "with Coach Mark S."). Tap → cross-role drawer with read-only event info + a primary CTA "Switch to athlete" (or "Switch to coach") that flips the active role and reopens the event in its proper full drawer. No drag, no actions on the tile itself — current role doesn't own this event.

Event Status System (6 states)

All non-Planned states share the same visual grammar: colored 10% bg tint + 1px perimeter + 3px left stripe + inline pill next to title. Pill appears inline (not absolute-positioned) — reads as part of the title. Colors map to semantic roles, not to coach/athlete roles.

  • Planned — teal (dark: teal-400 / light: teal-600) for personal, blue-400/600 for group. Base surface, no perimeter. No pill.
  • Request (incoming, pre-event) — yellow-600 perimeter + 10% yellow bg + yellow pill "Request". Athlete asked, coach needs to Accept/Decline.
  • Awaiting (outgoing, pre-event) — yellow-600 dashed perimeter, no fill + outlined yellow pill "Awaiting". Same “not confirmed yet” hue as Request but outline instead of fill: filled yellow = act on it, dashed outline = tentative, nothing to do. Previously gray-on-surface, which read as an ordinary Planned tile.
  • Review (post-event, unfinalized) — same yellow visual as Request. Event ended, coach hasn't opened Completion screen yet. Yellow because coach action needed — consistent lane with Request.
  • Missed — red-400 perimeter + 10% red bg + red pill "Missed". Explicit no-show or auto after N days without coach review.
  • Finished — base card at opacity 0.5, no pill, no perimeter. Past events that coach confirmed via Completion flow. Time + fade are sufficient signal; pill would be redundant.

Group events use only 4 of these states: Planned, Review, Missed, Finished. Request and Awaiting don't apply — group is a template, athletes join without approval.

Cancelled events disappear from calendar entirely (not a visible state). All visible statuses retained for 2 months, then archived.

24-hour vertical timeline, 15-min grid snap.

  • Day strip — colored dots under days: 🟢 personal, 🔵 group, ⚫ external
  • Group events — cyan border + badge "7/10"
  • Personal events — teal tint + teal stripe + athlete name (Group = blue tint + blue stripe). Same grammar in both themes; the alpha differs per theme (dark: accent-500 @10–12%, light: accent-600 @16–20%) so both land the same distance off their canvas.
  • Status pills — inline with title (not absolute-positioned). Filled yellow = Request or Review (coach action needed), dashed/outlined yellow = Awaiting (passive wait), red = Missed, no pill = Planned or Finished. See Behavior details for full system.
  • External events — gray, opacity, side-by-side with the hatched blocked zone
  • Cross-role events — dashed-stripe muted tile + role tag (e.g. "Athlete"). Tap → drawer with read-only info + "Switch to athlete" CTA. See Behavior details.
  • Off-hours — full 00:00–24:00 grid; hours outside availability get a full-bleed flat wash + dimmed labels + a centered label per segment (hatch is reserved for “blocked”). Auto-scrolls to the working band on open.
  • FAB "+" → sheet: Personal, Group, Custom event
  • Long tap empty slot → same sheet, time prefilled
  • Tap event → event action sheet (personal/group/invitation)
  • Long press event → activates drag & drop (same day only)

Group Event Detail

Invite & deep-link

Share link

Generated on-demand via Appsflyer OneLink when coach taps Invite — not pre-generated for all future events. Short URL (321.fit/e/xK3aB) carries event_id in attribution params.

Rescheduled/cancelled events

Deep link resolves by event_id, so reschedule doesn't break it. If event cancelled before athlete opens → app shows "Event unavailable" and redirects to coach profile.

Caching

Backend caches short URL per event_id (1 Appsflyer call per event lifetime). Client caches per session.

"Ticket card" layout — compact summary + note + participants.

  • Ticket: badge + price, date/time, location, spots bar
  • Note to athletes — instance-only ad-hoc message (e.g. "bring a mat"). Tap to edit. Empty state = dashed "Add a note" CTA. Changes trigger push to all participants.
  • ⋯ menu (top-right) → Invite / Reschedule / Cancel training
  • Footer CTA → "Invite athletes" (primary) when spots available; "Complete Training" for past events
  • Tap participant → athlete profile (clients module)
  • Swipe left or × → remove with 5s Undo snackbar (batched for multiple, commits after 10s max)
  • Long press → quick actions sheet (Profile, Message, Remove)
  • Empty state (Empty toggle): no participants, no note, dashed CTA visible

Entry point

Unpaid cash

Does NOT block completion. Stays as cash_pending record. Coach can see unpaid athletes in training history.

Post-training screen. Coach reviews payments and completes training.

  • Card participants: auto "Paid" badge, no action needed
  • Cash participants: checkbox, swipe right/left, long press
  • Payment summary: "4 paid · 1 unpaid"
  • Each row shows payment method (Card/Cash)
  • Complete Training → triggers Stripe transfers for card
Coach

Busy time

Secondary FAB action. Coach creates a custom calendar block — no athlete, no training session template. Renders on timeline as muted block, blocks athlete booking calendars for this slot. Renamed from "Block time off" to disambiguate from Availability → Time off (multi-day vacation). Busy time = one ad-hoc slot; Time off = a date range that pauses all bookings + messages clients.

  • Title (optional, defaults to "My time") — free text, e.g. "Dentist", "Errand", "Gym closed"
  • All-day toggle — when on, hides start/end time row and blocks the whole day
  • Cross-link note → Time off: outline card at the bottom routes coaches who actually want a multi-day absence to available-hours.html#timeoff (a11y coach.calendar.block.timeoff-link). Shown always; the all-day case is the classic "I really mean vacation" signal.
  • Date opens calendar grid sheet (single date in v1; multi-day deferred)
  • Start / end time — two side-by-side pickers
  • Notes (optional, 0–300 chars) — only visible to coach
  • Save → POST /coach/events with type: custom, no training_session_id, no athlete_profile_id
  • Athlete-side visibility: appears as Coach unavailable on booking calendar — title and notes are NEVER exposed to athletes

Backend dependency: custom event endpoint to be added per coach-calendar.md § Flow 5. Backend currently has nullable athlete_profile_id + training_session_id on TrainingEvent — schema supports custom events; controller/handler need adding.
