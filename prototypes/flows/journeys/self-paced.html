Self-paced training — end-to-end
Self-paced is an online / async session: the coach offers a cheap generic template, the athlete books it for a day (no time slot), the coach builds a per-athlete workout, the athlete plays it step-by-step and submits proof, the coach reviews — and the per-session comments thread is the home for the whole exchange. Lifecycle: Requested → Ready → Submitted → Finished.
References, not duplicates — every step opens the canonical surface, so this never drifts from the source. Use the browser back button to return here.  ·  The screens still live in the isolated module shared/self-paced.html#<anchor> (split into real surfaces per self-paced.md §5); integration entry points below open their real screens.
Online / async · no time
Booked for a day, not a time slot — the card reads “Self-paced · do it anytime” (clock icon, deliberately not “Online”, to avoid confusion with live online sessions).
Per-athlete setup
Every booking becomes a request the coach builds by hand — a master–detail builder (step list + focused step editor), not one long form and not a rigid wizard.
Sequenced player
An exercise is a Freeletics-style sequence: Get-ready 3-2-1 (voiced) → work → rest (auto-flow). One focus per phase, one action, voice cues, one thin progress bar.
Thread = home
The per-session comments thread is where it lives — the athlete’s submission and the coach’s review are anchor messages, then free replies.
Lives in existing surfaces
No new bell, no 4th tab. Requests + reviews go to the unified Inbox; Dashboard rows + Client Detail summary surface it. Athlete list is not a tab.
Packages apply
A pack is N sessions of one template — self-paced is just a template type. Priced on the offering (below the live rate); card / cash / both. See session-packages.md.
